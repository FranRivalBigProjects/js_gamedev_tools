How 2D Canvas Physics Simulation Works in JavaScript

This sandbox uses vanilla JavaScript and the Canvas API — no Matter.js, no Box2D, no external libraries. Understanding the underlying physics code is the fastest way to learn game physics for your own projects.

Every frame, three steps run in sequence: physics update (apply gravity and velocity to position), collision detection (check all object pairs and walls), and render (clear canvas and draw updated positions). The loop runs via requestAnimationFrame for ~60fps.

// Core game loop — the foundation of every physics simulation function gameLoop(timestamp) { const dt = (timestamp - lastTime) / 1000; // delta time in seconds lastTime = timestamp; update(dt); // apply physics collide(); // detect + resolve render(); // draw frame requestAnimationFrame(gameLoop); }

Gravity //

Applying Gravity

Each frame: vy += gravity * dt. Gravity is constant downward acceleration. Multiply by delta time to keep simulation frame-rate independent. Higher gravity = faster falling objects.

Collision //

Collision Detection

Circles: dist < r1 + r2. Boxes: AABB overlap check on x and y axes simultaneously. After detection, collision resolution separates objects and reflects velocities using the restitution coefficient.

Elasticity //

Coefficient of Restitution

After a wall collision: vy = -vy * restitution. Value 1.0 = perfect bounce (no energy loss). Value 0.0 = no bounce. Try the elasticity slider to see the difference — at 0.0 objects stick to the floor.

Friction //

Damping / Friction

Each frame: vx *= friction. Values close to 1.0 preserve velocity (slippery). Values like 0.9 slow objects quickly. This simulates air resistance and surface friction without complex contact math.

What Developers Ask About Canvas Physics in JavaScript

How do I implement circle-circle collision detection in JavaScript?
Calculate the distance between centers: dist = Math.sqrt((x2-x1)² + (y2-y1)²). If dist < r1 + r2, the circles overlap. For resolution: calculate the overlap amount, then move each circle apart by half the overlap along the collision normal. Reflect velocities along the normal using the restitution coefficient. For performance with many objects, use spatial hashing or a quadtree to avoid O(n²) checks — checking every pair is fine up to ~100 objects.

What is delta time and why does it matter for physics?
Delta time is the time elapsed since the last frame (typically ~16.6ms at 60fps). Multiplying physics by delta time makes the simulation frame-rate independent — objects move the same distance per second regardless of frame rate. Without it: on a 30fps machine objects move at half speed, on a 120fps machine they move twice as fast. Always write physics as position += velocity * deltaTime not just position += velocity.

Should I use requestAnimationFrame or setInterval for a game loop?
Always requestAnimationFrame for rendering. It syncs to the display refresh rate, pauses when the tab is hidden (saving battery), and provides a high-precision timestamp. setInterval is appropriate for fixed-rate game logic (like a network tick) but not for rendering. The pattern used in this sandbox: requestAnimationFrame for the render loop, with delta time capped at ~50ms to prevent physics explosions after tab unfocus.

Why does my simulation explode (objects fly off screen) at high speeds?
This is the "tunneling" problem — a fast-moving object can pass completely through a wall in a single frame because the frame time is too large. Solutions: cap your delta time to prevent large physics steps, use sub-stepping (run physics 2-4× per frame with smaller dt), or add a velocity cap (vx = Math.min(Math.abs(vx), MAX_VEL) * Math.sign(vx)). The sandbox uses both delta time capping and velocity limits to stay stable.

Frequently Asked Questions

Vanilla JavaScript and the HTML5 Canvas API — no Matter.js, no Box2D, no external libraries. The physics loop runs via requestAnimationFrame. Each frame applies gravity, updates positions, runs AABB and circle collision detection, resolves overlaps, and redraws. The full physics engine is under 200 lines of JS.
The coefficient of restitution determines how much kinetic energy is preserved after a collision. 1.0 = perfect bounce (all energy preserved). 0.0 = no bounce (objects stick). Real materials range from ~0.1 (clay) to ~0.85 (rubber). The elasticity slider in the sandbox controls this value — try dragging it to 0 and 1 to see the difference.
AABB (Axis-Aligned Bounding Box) collision checks whether two rectangles overlap by comparing their x and y ranges. Circle collision checks if the distance between centers is less than the sum of radii. Circle collision is faster to compute and more accurate for round objects. AABB is faster for rectangular objects. Most games use both and switch based on object shape.
For learning: build from scratch first — you'll understand gravity, collision resolution, and the game loop. For production: Matter.js handles complex shapes, constraints, joints, sleeping bodies, and has good documentation. It adds ~80KB gzipped. For very simple games (fewer than 50 objects, basic shapes), vanilla JS physics like this sandbox is lighter and faster.
